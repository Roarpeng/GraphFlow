# GraphFlow 成长计划

> 调研驱动版 · 基于 v1.17.0 代码现状 + 文献/工业界/社区证据
> 本文档回答一个问题：**GraphFlow 接下来该往哪长，哪些方向必须放弃。**
> 证据调研范围：8 路主题调研 + 2 路补充调研（记忆架构与基准、经验→技能库与迁移、上下文工程与压缩、持续学习与遗忘、检索触发策略、归因与评测、元认知与校准、社区与竞品）+ 4 路对抗性验证（红队证伪）。

---

## 0. 先读这一段：调研推翻了两条"显而易见"的直觉

上一轮基于代码现状的判断是：GraphFlow 的缺口是「召回是拉取式」和「巩固没有自动节律」，所以应该（a）把记忆自动推送进上下文，（b）把 reflect/consolidate 挂上自动节律。

**调研结论是：这两条的无条件形式都是错的。**

| 直觉 | 证据裁定 | 可采纳的形式 |
| --- | --- | --- |
| 把记忆/技能推送进上下文更好 | **mixed**。选择性、可沉默的推送有效（Terminal-Bench 2.0 +8.3pp、τ²-Bench +6.8pp，arXiv:2607.08716）；但常开注入更差，且在编码 Agent 上唯一头对头对照（288 次运行、注入策略为唯一变量）**正确率无可测变化**（arXiv:2607.27250）。Claude Code 的自动记忆实测占小 subagent 首轮上下文 **34%（7,133 token）**且无法退出（issue #87613） | 只推**极小索引**（技能名 + 一句适用条件 + 验证状态），不推正文；选择性、可沉默、与拉取并存 |
| 时间衰减 + 离线巩固是必要的 | **mixed**。无门控的持续巩固会让记忆效用**先升后降到无记忆基线以下**（arXiv:2605.12978）；确定性版本/时间戳判定比衰减和 LLM 时效判断更准（**+10.8pp**，arXiv:2606.01435）；睡眠式巩固的正面证据来自**权重侧**，不适用于纯文本存储。领域自承"没有人认真评测过遗忘" | 陈旧处理用**确定性失效**（符号/版本/有效区间）而非时间衰减；巩固必须选择性、延迟、**可回溯可逆**；原始 episode 永久保留为一等证据 |

同时调研给出了一条**比"推送"重要得多**的主线：**这个领域的瓶颈不是"记得住"，而是"选得准 + 写得严 + 失效得快"。**

## 1. 调研的七条核心结论

### 1.1 瓶颈是选择精度，不是存储容量

- 技能池从 5 增到 100，**实际有效使用精度从 29.6% 掉到 3.3%**；202 个技能的库使 pass rate 平均掉 **21%**，其中最多 **68% 由"选错技能"（skill shadowing）解释**，而上下文变长（context overhead）的效应与 0 统计上不可区分（arXiv:2605.24050、arXiv:2608.14036）。
- 这不是 LLM 时代的新问题：工具数超过约 30 个后选择准确率显著下滑；语义检索预筛可把工具选择准确率从 **13.62% 提到 43.13%** 并把 prompt token 降一半以上（RAG-MCP，arXiv:2505.03275）。
- **推论：GraphFlow 该投资的是召回/路由层与索引设计，不是扩大技能库。**

### 1.2 写入门控是单点收益最高的机制

- 在写入时按复合显著性（来源可信度、新颖度、可靠性）过滤，再配版本链：**100% 准确率 vs 无门控的 13%**；在 8:1 干扰比下，读时过滤（Self-RAG）**崩到 0%**，写时门控保持 100%（arXiv:2603.15994）。
- 结构性原因：**读时的策展无法恢复本不该被存进去的信息。**
- 社区侧完全一致：开发者最大的抱怨不是"记得不够"而是"记忆有害"——HN 高热讨论中资深用户称长期记忆让 Agent 变笨、跨项目串味，**全局关闭**改用项目文档（news.ycombinator.com/item?id=47914367）。真实抱怨集中在三点：检索不准、记忆污染（临时决策被固化并跨会话传染）、旧事实不失效。**几乎无人抱怨容量。**

### 1.3 技能飞轮有效，但收益来源被普遍误判

- 有效，但量级依赖任务能否被"流程稳定化"：8,135 条对照试验中，蒸馏技能比直接注入原始轨迹平均高 **6.06 分**，而收益主体是**执行稳定（程序锚定 65.7%）而非知识补充（知识注入 4.5%）**。
- 提升**不来自"检索到相似任务"**：精确命中 ground-truth 技能既非充分也非必要；真正可复现的驱动因素是**把检索到的技能改写适配当前上下文**，去掉这一步就退化到朴素重放水平（arXiv:2607.28272）。
- 硬上限：SWE-Skills-Bench 在 49 技能 × 约 565 个真实仓库任务的配对评估下，**39/49 技能通过率提升为 0，平均仅 +1.2%，3 个致性能下降，token 开销最高 +451%**（arXiv:2603.15401）。
- 流行的记忆方法在流式评测上**低于"不使用记忆"的 baseline**：AWM 0.48、LangMem 0.49、Dynamic Cheatsheet 0.52，均低于 **0.54**（Evo-Memory，arXiv:2511.20857）。

### 1.4 失败轨迹必须与成功轨迹同等入库

- ExpeL 靠 fail/success 配对比较抽取洞察；SWE-Exp 的多层次经验库**同时保留成功与失败修复尝试**才达到 SWE-Bench Verified Pass@1 **73.0%**（arXiv:2507.23361）。
- **GraphFlow 当前的 proven 偏向 + anti-pattern/noise 清理，可能正在丢弃信息量最大的对比信号。**

### 1.5 无外部反馈的自我反思是负资产

- 仅靠模型自身能力的 intrinsic self-correction 在推理任务上**不提效甚至掉点**（Huang et al., ICLR 2024, arXiv:2310.01798）；自批评可导致性能崩塌，**只有可靠外部验证器有增益**（ICLR 2025, Stechly 等）。
- 元认知侧同构：模型会**系统性误判自身知识边界**（arXiv:2604.19749），但可用**自身历史结果**做统计/偏好对齐修正，无需重训基座。
- 关键陷阱是**校准 ≠ 行动**：言语置信度可校准，模型却不据此弃答，提示无效，**必须由 harness 外部强制阈值**（arXiv:2601.07767）。
- 编码域已实证：提交率 **100%** 对解决率 **44%**，失败中 **68–80% 是"自信且一致"的语义错误**，而完成率/一致性监控恰在最该不信任时显示健康（arXiv:2603.25764）。

> **推论：GraphFlow 用"agent 自报布尔 outcome"驱动的反思链，因果上是弱的。** 这是缺口 (3) 的真实严重程度——比"缺反事实模块"更根本，是 **outcome 的真相来源**问题。

### 1.6 迭代式重写压缩是有害的；有价值的是 O(1) 读路径

- 对上下文做迭代式重写压缩会同时触发 **brevity bias 与 context collapse**，正确做法是**结构化、增量式追加 + 策展**（ACE, ICLR 2026, arXiv:2510.04618）。这与"consolidate 式摘要合并"的直觉相反。
- 压缩的伤害集中在**精确回忆**而非语义问答：gist 压缩在 RAG/长文档 QA 上损失轻微，在 synthetic recall 上明确失败，三种失效模式为 lost by the boundary / lost if surprise / lost along the way（ACL 2025 long.241）。
- Claude Skills 的 progressive disclosure 之所以成立，靠的是**元数据（约 100 token）常驻 + 正文命中才读 + 代码只回传输出**这套 **O(1) 读路径机制**，不是"压缩"本身（Anthropic Engineering, 2025-10）。
- Context rot：只要插入 **1 个**主题相关但不回答问题的 distractor 就低于无干扰基线；聚焦输入（约 300 token）在**所有**模型族上显著优于完整输入（约 113k token）（Chroma, 2025-07）。
- 但"位置效应"（Lost in the Middle）在**现代 LLM 上不稳定**，主题采样是方差主因，oracle 检索设定下的结论不能迁移到真实 RAG 管线（arXiv:2605.27105）；RAG vs 长上下文**无银弹**，取决于模型/长度/任务（LaRA, ICML 2025）。

### 1.7 行业已收敛出一套生产配方，且它和 GraphFlow 现有缺口高度重合

Microsoft VS Code 的 Agent 记忆是当前最可直接对照的生产参考架构：

- 三种作用域（user / repository / session），**只有 user memory 的前 200 行自动加载**；
- 仓库级洞察**自动捕获**，跨 coding agent / code review / CLI 共享；
- 使用前**对当前代码库校验**（verify against the current codebase）；
- **28 天自动过期**。

即：**推一个很小的有界前缀 + 按需拉取 + 用前对代码校验 + 定时失效**。GraphFlow 的缺口 (2)(4) 正是这套配方的后两项。

## 2. 战略重定向

### 2.1 一句话

**从"记得更多"转向"选得更准、写得更严、失效得更快、被证得更实"。**

GraphFlow 的 α 不在记忆容量（那已是红海且被证明不是瓶颈），而在它**独有的资产**：一个 12 语言的 AST 代码图谱 + 带时间语义的对话图。这给了两件通用记忆层拿不到的东西：

1. **确定性失效信号**——技能引用的符号/文件路径不再解析时，技能应直接不可召回（硬约束），而不是等时间衰减降权。这是比 TTL 或衰减曲线更强的陈旧信号。
2. **可执行的验证器**——代码是少数自带 ground truth 的领域（测试通过/构建绿/类型检查）。这正好补上 §1.5 的"外部验证器"缺口。

### 2.2 指标换轨（这是所有其它工作的前提）

当前对外北极星是 **token 节省率 95.6% / 98.5%**。证据表明这作为**核心**指标是错的：

- 削减 38.4% 工具输出 token，**计费成本反而 +6.8%**，每任务相关 r=0.15；激进压缩使 SWE-bench Go 子集 patch 成功率从 **27/40 掉到 15/40**（破坏逐字编辑锚点）（arXiv:2607.12161）。
- 压缩导致约束遵循下降 28.6pp（91.9%→63.3%），而标准任务成功指标对其中 20.6% 的违规是**盲的**。
- 反证存在：SWE-Pruner 在 SWE-Bench Verified 上 token 减 23–54% 且成功率上升（arXiv:2601.16746）；"Less Context, Better Agents" 达 91.6% 完成率 / 553K token（对比完整历史 71.0% / 1.48M，arXiv:2606.10209）。

**裁定：放弃"节省率是核心指标"，而非放弃节省率本身。**

**新指标体系（照抄现成的，不要自创）**：SWE-Bench-CL 已为编码 Agent 定义持续学习指标套件——**平均准确率、遗忘、前向/后向迁移、工具使用效率、复合持续学习分数**，并显式对比 memory-on / memory-off（arXiv:2507.00014）。另补一个本领域最缺的指标：**技能有效使用精度**（被调用且确实有帮助 / 被调用次数）。

## 3. 阶段计划

每项给出：依据 → 动作 → 验收 → **失败判据**（预注册，防止事后解释）。

### P0 · 补上真相与约束（不做这些，后面全是给空气调参）

#### M1 · 指标换轨
- **依据**：§2.2
- **动作**：`diagnose` 与 README 的对外主指标从节省率改为能力指标（一次通过率、返工率、遗忘/迁移）；节省率降为**成本约束项**；引入 memory-on / memory-off 配对报告。
- **验收**：`npm run proof:flywheel` 输出含 memory-on/off 配对与等效性区间，且能在一个真实仓库上产出非零样本。
- **失败判据**：换轨后连续两个版本仍无法产出非零配对样本 → 说明数据采集路径本身没通，回到数据通路问题而不是指标问题。

#### M2 · 写入门控 + 来源与撤回链（最高单点收益）
- **依据**：§1.2（100% vs 13%）
- **动作**：episode / skill / dialogue 写入前做复合显著性门控（来源、新颖度、是否与既有记忆冲突）；每条记忆携带来源与**撤回链**，临时决策可被显式撤回；冲突时进入待复核而非静默覆盖。
- **验收**：构造 8:1 干扰比的对内测试，门控版显著优于无门控版；`graphflow diagnose` 能报出"被门控拒绝的写入数"与"被撤回的记忆数"。
- **失败判据**：若门控使真实有效记忆的**漏存率**高到影响任务成功率，则说明阈值定错——收紧/放宽，但**不取消门控**。

#### M3 · 技能选择精度（攻击 shadowing）
- **依据**：§1.1（29.6%→3.3%、shadowing 解释 68%）
- **动作**：首轮/按需推送**极小索引**（技能名 + 一句适用条件 + 验证状态 + 最后验证 commit），不推正文；召回加语义预筛（目标：选择准确率向 43.13% 靠）；实现 **shadowing 检测**：记录"召回了哪些 / 实际用了哪个 / 是否用错"，作为一等指标。
- **验收**：技能有效使用精度可测量且不随技能库增长而崩塌（在 50+ 技能规模下不出现量级下滑）。
- **失败判据**：若精度随规模下滑不可挡，则**主动限制技能库规模**并靠淘汰维持——规模不是目标。

#### M4 · 确定性失效替代时间衰减
- **依据**：§0 第二行、§1.3、§2.1
- **动作**：索引重建时校验技能引用的符号/路径是否仍解析；不解析则**直接不可召回**（不是降权）。陈旧处理以确定性版本/有效区间为主，时间衰减退为辅助。
- **验收**：能报告"因符号消失而退役的技能数"；构造"删符号后旧技能仍被推荐"的回归测试必须失败（即修复生效）。
- **失败判据**：若绝大多数技能都不绑符号（无法校验），则说明技能抽取阶段的原子化不足——修抽取，而非退回时间衰减。

#### M5 · 能力地图（元认知，成本最低、证据最一致）
- **依据**：§1.5（历史结果可修正边界自知；必须外部强制阈值）
- **动作**：按任务域/语言聚合 episode 的 (n, 成功率, 最近验证时间)，**由 harness 外部计算**（不让模型自报置信度）；当 n < k 或成功率低于阈值时，显式向 Agent 报"此域无已验证记忆 / 技能未经验证"，允许其升级或弃答。
- **验收**：能在真实会话中正确报出"我不知道这块"；提供 AUARC（覆盖率-准确率）与弃答率。
- **失败判据**：若"不知道"信号导致可用性/信任显著下降（用户反复被拒），则降级为**建议**而非强制。

### P1 · 让学习真的与能力挂钩

#### M6 · 失败轨迹入库
- **依据**：§1.4（ExpeL / SWE-Exp 73.0%）
- **动作**：把失败修复尝试与成功路径**同等**存储为一等证据，保留"错在哪、为什么改对"的对比结构；anti-pattern 不是被清理对象而是学习信号。
- **验收**：给定同一任务的成功/失败对，系统能产出可复用的对比洞察；技能准入能引用它。
- **失败判据**：若失败轨迹导致负迁移（新任务被错误旧经验带偏），则加"适用性判别"环节而非删除失败轨迹。

#### M7 · 结构化增量追加，禁止有损重写式巩固
- **依据**：§1.6（ACE：brevity bias / context collapse）
- **动作**：consolidation 改为**冲突检测 + 增量追加 + 策展**，保留明细；有损摘要只允许发生在明确需要时且必须可回溯到原文。原始 episode **永不删除**。
- **验收**：巩固前后可回溯性（任意结论能追到原始 episode）100%；无"巩固后信息丢失"的回归用例。
- **失败判据**：若巩固无法在能力指标上显示正向收益，**就不自动跑它**（这是与现有 ROADMAP 的明确分歧）。

#### M8 · 可执行验证器替代自报结局
- **依据**：§1.5（自评不可靠；仅外部验证器有效）
- **动作**：技能准入与 `proven` 判定必须以**可执行证据**为准（测试命令 + 结果、构建、类型检查、commit），而非 agent 自报布尔值；无外部证据一律停在 provisional。
- **验收**：proven 技能的每一条都能给出验证命令与结果；`userConfirmed:false` 且无测试证据的不得进入 proven。
- **失败判据**：若多数任务无法自动验证（取不到测试），则先建立"人工确认的最低成本通道"，**而不是**放宽自报。

#### M9 · 推送的窄形态（保留拉取）
- **依据**：§0 第一行、§1.2、§1.6
- **动作**：只在"长程任务中缺乏检索信号的行为状态"上做**选择性、可沉默、低量**推送；推索引与状态，**不推正文**；与 `graphflow_context` 拉取并存，不做替代。
- **验收**：真实编码任务上的 A/B（pass rate 为主指标 + 等效性区间 + 误报污染率），且可一键关闭。
- **失败判据**：若无正向增益或污染代价超阈值，**回到纯拉取**并只保留索引推送。

### P2 · 差异化：做别人做不了的事

#### M10 · 跨项目：先共享索引与接口，正文按项目改写
- **依据**：§1.3（证据混杂：Agent KB/AWM 正面，负迁移/shadowing 负面）。**当前属于未验证方向，不是确认缺口。**
- **动作**：跨项目只同步**索引与接口描述**（成本低、与三级渐进披露天然兼容），正文按项目改写；先做"可迁移技能 vs 项目约定"的判别实验。
- **验收**：能判别出一条技能是"可迁移原则"还是"本项目约定"，并在跨仓库实验中显示正向迁移。
- **失败判据**：若无法判别或触发 shadowing，**放弃跨项目泛化**，退回普通同步。这是明确允许砍掉的方向。

#### M11 · 反基准（信任是当前最稀缺的资源）
- **依据**：社区证据——LOCOMO 答案键 6.4% 错误、判官接受 62.81% 的故意错答；Mem0 同基准自报 92% / 93.4% 两值；Zep 自报 71.2% 被独立复现为 63.8%（getzep/zep-papers issue #5）；Mem0 OSS 复现 53.83%/56.04% 对论文 60%+，维护者承认"论文数字来自 SaaS 不是 OSS"（mem0ai/mem0#3943）。
- **动作**：所有公开数字附 harness、数据集划分、检索种子、per-case 工件、判官误判率；先把现有 token 节省率按同一标准重报。
- **验收**：第三方可按文档在无作者参与下复现。
- **失败判据**：—（这项是纯增益，无失败模式）

#### M12 · 巩固的自动节律（放在最后，且可逆）
- **依据**：§0 第二行（睡眠式巩固的正面证据来自权重侧；无门控持续巩固可低于无记忆基线）
- **动作**：在 M2/M4/M6/M7 完成后才接自动节律；巩固必须选择性、延迟、可回滚；以能力指标验收而非"整理得更整齐"。
- **验收**：自动巩固开启 vs 关闭的配对实验显示能力指标正向且无回归。
- **失败判据**：**若无正向证据，保持手动 CLI。** 不因为"人需要睡眠"的类比而实现它。

## 4. 明确不做（Negative Roadmap）

| 不做 | 为什么 |
| --- | --- |
| 把记忆/技能**正文**自动注入上下文 | 实测占小 subagent 首轮 34%（#87613）；常开注入劣于选择性干预；shadowing 惩罚会吃掉收益 |
| 以**时间衰减**为核心陈旧机制 | 确定性版本/时间戳判定比衰减与 LLM 时效判断更准（+10.8pp）；衰减的独立对照实验**未被检索到** |
| **无门控**地自动跑 consolidate / decay / prune | 无门控持续巩固可低于无记忆基线（arXiv:2605.12978）；ACE 证明重写压缩有害 |
| 追求**技能库规模** | 202 技能 → pass rate -21%，精度 29.6%→3.3%；产业界把上限推到 500 与实测冲突，尚未收敛 |
| 只沉淀**成功**技能 | 失败轨迹是信息量最大的信号（ExpeL / SWE-Exp） |
| 让模型**自报**置信度与结局并据此学习 | 自评不可靠（ICLR 2025）；校准 ≠ 行动，须外部强制阈值；编码域 68–80% 失败是"自信且一致"的 |
| **改权重**（微调 / 测试时训练） | 现有架构价值在于冻结 θ、只演化外部记忆；权重侧是另一条产品线 |
| 把"节省 token"当作**对外主指标** | 削 token 可能增成本（r=0.15），且破坏逐字编辑锚点 |

## 5. 实验与度量纪律（防止自欺）

这个领域的数字已被默认当作营销，GraphFlow 的机会正是**诚实**。

1. **预注册**：每个里程碑动手前写下验收标准与失败判据（本文档第 3 节已给）。
2. **配对而非聚合**：同任务配对 A/B。聚合成功率会被"只在简单任务上检索"的选择偏差污染——Skill Following 显示多数模型聚合增益为正而**同任务实际使用效应为负**（arXiv:2609.00549）。
3. **报等效区间**：不只报"有提升"，要报"无提升的界"。GraphFlow 目前的自证只验"目标是否出现在 Top-5"，README 却称其为 task success——这个口径差必须修掉。
4. **per-case 工件**：公开判官误判率、数据集划分、检索种子。
5. **确定性优先**：任何时效判断优先用确定性规则（版本/时间戳/符号解析），LLM 判断只作补充。
6. **能力指标多维**：Token 与准确率是最容易被做成不可复现的两个数字——至少同时报准确率、progress rate、step efficiency、sequence robustness（Evo-Memory 四维）+ 工具使用效率。

## 6. 风险与单人维护约束

- **bus factor = 1**：每个里程碑必须可独立回滚，禁止跨模块大重构（v1.16/v1.17 已完成两次结构性拆分，短期不再做）。
- **优先级反直觉带来的组织风险**：M1（换指标）会让对外叙事变弱——从"省 95.6% token"变成"一次通过率提升 X%"。这是**必要**的诚实性代价，但需要主动沟通（README/ROADMAP 同步改写，避免出现"说一套测一套"）。
- **最大的战略风险**：宿主（Claude Code / Cursor / Copilot）把记忆内化为运行时能力，让独立本地记忆层变得多余。**唯一防御是它们做不到的两件事**：跨宿主可移植（19 宿主已是优势）+ 基于 AST 图与可执行验证器的确定性失效与验证。这也是 M4/M8 的战略意义所在，不只是功能点。
